# Record event-day check-in Task Specification

## Basic Information

- **Task ID:** T8
- **Task name:** Record event-day check-in
- **Task type:** Act
- **Task owner:** CPVC Event Organizer

## 1. Task Description

Logs the physical arrival of a participant during the event check-in window. This updates their status to confirm actual attendance, overriding any previous forecasts or expected statuses.

## 2. Inputs

### Input 1

- **Input name:** Attendee Check-in Scan
- **Contents and format:** A unique participant ID string generated by scanning a ticket or manual entry at the door.
- **Source:** Event check-in desk (via D11)

- **If a required input is missing or invalid:** Display an `invalid_id` error on the check-in terminal and instruct the human staff to manually verify the attendee.

## 3. Outputs

### Output 1

- **Output name:** Checked-in Status Record
- **Contents and format:** Database update changing the participant's status to "Checked in" with an exact timestamp.
- **Next task or recipient:** D9: Has the check-in window closed?
- **Complete when:** The database confirms the write operation is successful.

## 4. Planned Tools

### Tool 1

- **Tool name:** `record_check_in`
- **Input:** Attendee Check-in Scan
- **Output:** Checked-in Status Record
- **Implementation Route:** database queries
- **Integration approach:** direct integration
- **Role in this task:** Writes the exact arrival time and updates the attendance flag in the master roster.
- **Task timeout:** 5 seconds
- **Maximum retries:** 1
- **Retry only when:** The database encounters a concurrency lock, waiting 1 second. To avoid duplicate check-in logs, do not retry if the network drops after sending the request.
- **On timeout, exhausted retries, or an error that cannot be retried:** Record `check_in_failed` and instruct desk staff to log the arrival manually.
